# Рабочая область и журнал инцидентов — политика 1.0.0

Общая политика Git TWYLT Pack 0.3.0 и Filesystem TWYLT Pack 0.5.0 (политика без изменений с 0.2.0).
Это несовместимое изменение семантики путей: перед запуском настройте runner.

## Настройка запуска

```bash
# Каталоги создаёт администратор/владелец runner, до запуска инструментов.
mkdir -p /srv/agent/workspace /srv/agent/logs
export TWYLT_WORKSPACE_ROOT=/srv/agent/workspace
export TWYLT_INCIDENT_LOG=/srv/agent/logs/workspace-incidents.jsonl
```

Для Windows cmd (сначала создайте эти каталоги):

```bat
set "TWYLT_WORKSPACE_ROOT=C:\agent\workspace"
set "TWYLT_INCIDENT_LOG=C:\agent\logs\workspace-incidents.jsonl"
```

| Переменная | Требование |
|---|---|
| `TWYLT_WORKSPACE_ROOT` | Обязательный абсолютный физический путь к существующему реальному каталогу. Не корень диска/ОС. Без symlink/junction в нём или его предках. |
| `TWYLT_INCIDENT_LOG` | Необязательный абсолютный физический путь к JSONL-файлу **вне** рабочей области. Родительский каталог должен существовать. Если переменная отсутствует/пуста, инциденты пишутся в stderr. |

Настройки передаёт доверенный runner. В JSON инструмента нет переключателя,
который отключает проверку или меняет корень/журнал. Неверная/отсутствующая
конфигурация отклоняет бизнес-операции; describe/help/version продолжают работать.
Параметры окружения нужно сохранить в конфигурации именно runner ToolHub,
а не только в терминале, из которого собирался toolpack.

## Виртуальные пути

При корне `/srv/agent/workspace`:

| Вход | Физический объект |
|---|---|
| `/` или `.` | `/srv/agent/workspace` |
| `/project/file.py` | `/srv/agent/workspace/project/file.py` |
| `project/file.py` | тот же файл, независимо от cwd |
| `../outside` или `project/../other` | отказ |

Даже старый физический абсолютный путь `/srv/agent/workspace/project`
будет интерпретирован как виртуальный: не передавайте его агенту.
Применяется единый POSIX-синтаксис `/` на всех ОС. `~`, backslash, Windows drive,
UNC, NUL и `:`/alternate data streams запрещены. `..` запрещён в любом сегменте,
включая нормализуемые пути внутри корня. На Windows также запрещены имена устройств
и окончания компонента точкой/пробелом. Unicode и пробелы внутри имени поддержаны.

В Git `repo` и локальный `clone.url`/`destination` — пути рабочей области;
`put.path`, `add.paths`, `diff.paths`, `status.paths`, `log.paths` — только
относительные пути **внутри repo**. В этих полях нельзя передавать ведущий `/`.
Пути `.git` через эти Git-поля запрещены.

Файловый пак возвращает виртуальные `path`/`source`, а `relative_path` — путь
от корня конкретного поиска. Git редактирует префикс физического корня в своём
итоговом stdout/stderr. Произвольное содержимое файлов, коммитов и ошибки внешних
сервисов не являются контролируемыми полями путей и могут содержать любой текст.

## Проверки

- Проверяется каждый компонент пути, включая существующих предков ещё не
  созданного файла. Symlink, dangling symlink и junction/reparse point запрещены.
- Регулярные файлы с `st_nlink > 1` запрещены: нельзя определить, находится ли
  другая жёсткая ссылка снаружи. Это также запрещает полностью внутренние hard links.
- Запрещены специальные файлы (FIFO, устройства, sockets) и компоненты с другим
  `st_dev` относительно корня. Bind mounts на том же устройстве этим не выявляются.
- Корень области нельзя удалить или переместить/заменить. При рекурсивных
  copy/move/delete всё дерево проходит preflight до начала изменения.
- list/find/glob могут показывать **метаданные самой символической ссылки**,
  не раскрывая и не посещая её цель. При фильтре access ссылки пропускаются.
  Наличие ссылки в списке не является инцидентом; попытка доступа через неё — является.
- Нарушение политики не подавляется режимом поиска `on_error=skip`.
- Результат проверки не является транзакцией. При обычной ошибке I/O после
  preflight операция по-прежнему может оказаться частично выполненной.

## Транспорт TWYLT

CLI JSON и stdin/stdout работают из любого cwd; пути данных всегда виртуальные.
При файловом режиме `input.json`/`output.json` cwd **должен находиться внутри
области**. Оба транспортных пути проверяются до того, как TWYLT удалит старый
output.json или прочитает input.json; output проверяется повторно перед записью.
Внешний cwd либо транспортная symlink/hardlink отклоняются с журналированием.
Имена транспортных файлов не меняются. `run.py` запускайте по пути к установленному
инструменту; сам код инструмента может находиться вне рабочей области.

## Инциденты

Журнал содержит **отказы политики**, а не полную историю успешных операций.
Обычные ошибки Git, отсутствие файла, ошибки схемы JSON или парсинга содержимого
не считаются инцидентами этой политики. Формат: одна JSON-запись на строку.

```json
{"event":"workspace_incident","schema_version":"1.0","timestamp":"2026-10-02T04:00:00+00:00","incident_id":"01234567-89ab-4cde-8fab-0123456789ab","tool":"fs_read","pid":1234,"action":"deny","code":"path_outside_workspace","requested_path":"../outside"}
```

`incident_id` также включён в стандартное исключение TWYLT `WorkspaceDenied`.
Поле `code` предназначено для машинной обработки; текст исключения — для диагностики.
`requested_path` присутствует только там, где проверялся путь, и обрезается до
1024 символов. Переводы строк/управляющие символы экранируются JSON. Содержимое
файлов, payload записи, URL remotes и credentials в журнал не добавляются.
Сами имена файлов могут быть чувствительными — доступ к журналу должен быть ограничен.

Основные коды:

| Код | Причина |
|---|---|
| `workspace_not_configured`, `invalid_workspace_root`, `filesystem_root_forbidden` | Нельзя использовать заданный корень |
| `path_outside_workspace`, `invalid_path_syntax`, `invalid_path` | Недопустимый путь |
| `symlink_forbidden`, `hardlink_forbidden`, `special_file_forbidden`, `mount_boundary_forbidden` | Запрещённый объект/переход |
| `workspace_root_mutation_forbidden` | Попытка изменить корень области |
| `invalid_incident_log`, `incident_log_inside_workspace`, `incident_log_unavailable` | Ошибка журнала |
| `transport_cwd_outside_workspace` | Файловый транспорт за пределами области |
| `git_config_forbidden`, `git_storage_redirection_forbidden`, `git_indirect_worktree_forbidden` | Неподдерживаемая небезопасная конфигурация/структура Git |
| `git_local_remote_outside_workspace`, `git_remote_forbidden`, `git_remote_not_configured` | Нельзя использовать remote |
| `git_symlink_tree_forbidden` | Получаемое дерево коммита содержит символические ссылки |
| `invalid_repository_relative_path`, `git_metadata_path_forbidden` | Недопустимый путь внутри repo |

Файл журнала создаётся в append-режиме с 0600 на POSIX (существующие права
не меняются); symlink/hardlink и не-регулярный файл журнала запрещены.
Перед бизнес-операцией проверяется открытие sink. Каждая запись выполняется одним
append-write и fsync; параллельные процессы проверены на локальной Linux FS.
Если настроенный sink не открывается/не принимает запись, запрос завершается
отказом; резервное событие поступает в stderr. Автоматического отключения
контроля/журнала нет. Ошибка записи содержит `original_code` исходного инцидента.
При ошибке самой настройки корня доступен только резервный stderr.

Без `TWYLT_INCIDENT_LOG` stderr содержит строку инцидента **перед** обычной
JSON-ошибкой TWYLT: это несколько JSON-строк, не один JSON-документ.
Для runner, ожидающего ровно одну ошибку в stderr, задайте отдельный файл журнала.
Ошибки sink всё равно имеют аварийный вывод в stderr — runner должен его сохранять.
Политический отказ в biz даёт стандартный exit 5; в файловом транспорте — exit 4.
Проверка схемы TWYLT может отклонить запрос раньше политики (exit 2, без инцидента).

Ротация и срок хранения задаются оператором вне инструментов (например, logrotate).
Инструменты не дают агенту операции для очистки этого внешнего файла. Это не
криптографически защищённый журнал; доверенный процесс с правами ОС может его менять.

## Git: дополнительные ограничения

Чтобы Git не обходил явные проверки через метаданные, применён строгий профиль:

- `.git` — реальный каталог; gitdir-файлы/linked worktree, commondir,
  objects/info/alternates и http-alternates отклоняются.
- Всё рабочее и служебное дерево проверяется на ссылки перед операцией.
  Это может замедлять большие репозитории. Фильтр paths не отменяет эту проверку.
- `.git/config` читается без includes и проверяется по allowlist безопасных ключей.
  include/includeIf, core.worktree, filters, custom SSH commands/helpers и прочие
  неизвестные настройки отклоняются. Точная allowlist — `src/git_policy.py`.
- Пользовательская и системная конфигурация Git отключены; user.name/email задайте
  локально в репозитории. Hooks, fsmonitor, submodule recursion и commit signing
  отключены. Global credential helpers также не подключаются.
- HTTPS/SSH и scp-style SSH remotes разрешены; SSH agent/SSH configuration —
  доверенная настройка runner. git://, file:// и внешние Git remote helpers
  не поддержаны. Сетевое содержимое не ограничивается этой файловой политикой.
- Локальные remotes разрешены только внутри области, вместе с их служебными
  хранилищами. Вход clone.url — виртуальный путь; сохранённый Git remote URL —
  физический абсолютный путь **внутри корня** (так его сохраняет clone).
  Относительные локальные URL в конфигурации не поддержаны.
- fetch/pull/push принимают имя заранее настроенного remote (или `.`), не произвольный URL.
- Локальный clone использует `--no-local`, исключая hardlink/shared object clone.
  Clone сначала загружает без checkout, проверяет дерево и только затем разворачивает
  его. Pull делает fetch, проверяет зафиксированный commit hash, затем ff-only merge.
  Деревья с symlink не разворачиваются. При отказе refs/объекты после fetch или новый
  каталог после clone могут остаться — автоматического удаления/отката нет.

## Граница гарантии

Это контроль явных и перечисленных неявных путей в обёртках, **не ОС-песочница**.
Проверка и обращение разделены во времени (TOCTOU): другой процесс с правом
переименования/создания ссылок может вмешаться. Нельзя считать область границей
для злонамеренного параллельного процесса, bind mount того же устройства,
скомпрометированного Git/SSH или произвольного исполняемого кода. Код инструментов,
окружение, системный Git, SSH и служебные каталоги runner должны быть доверенными.
Для строгой изоляции запускайте процесс в контейнере/ОС sandbox с нужными mounts.
В этой версии такой runner не создаётся и не настраивается.

Windows junction detection и Windows-синтаксис предусмотрены, но тесты этого
выпуска выполнялись на Linux. Не заявляется проверенная изоляция на Windows/macOS.
